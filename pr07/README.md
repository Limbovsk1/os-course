
# ПР-7. Межпроцессное взаимодействие — IPC (вариант B)

## Цель
Реализовать клиент–сервер тремя механизмами IPC и сравнить их.

## Задание 1. FIFO (именованный канал)

Сервер (терминал 1):
```
python3 fifo_server.py
```
Клиенты (терминал 2):
```
python3 fifo_client.py 3 4      -> 3 + 4 = 7
python3 fifo_client.py 10 20    -> 10 + 20 = 30
```

Сервер создаёт FIFO /tmp/osfifo_req (os.mkfifo), читает запросы вида
"pid a b" и пишет сумму в персональный FIFO ответа клиента
(/tmp/osfifo_reply_<pid>). Клиенты создают свой FIFO ответа, шлют запрос и
ждут ответ в read(). Сервер последовательный: клиенты обслуживаются по
очереди, второй ждёт, пока первый не получит ответ.

## Задание 2. Unix-сокеты (AF_UNIX), параллельные клиенты

Сервер (терминал 1):
```
python3 unix_server.py
```
Клиенты (терминалы 2 и 3, можно одновременно):
```
python3 unix_client.py 5 6      -> 5 + 6 = 11
```

Сервер на каждое соединение делает fork и обслуживает клиента отдельным
процессом — клиенты работают параллельно, в отличие от FIFO-версии.
Сокет /tmp/oscourse.sock при выходе удаляется.

## Задание 3. SharedMemory vs Pipe (массив 10^7 чисел)

```
python3 shm_bench.py
```

Вывод:

```
Pipe:         0.642s  sum=49999995000000
SharedMemory: 0.483s  sum=49999995000000
```

Pipe: список сериализуется (pickle) и копируется через ядро дважды
(родитель->буфер ядра->ребёнок). SharedMemory: одно копирование массива в
общий сегмент (mmap), дочерний процесс наследует отображение при fork и
читает данные напрямую, без системных вызовов на каждую порцию. Разделяемая
память быстрее на ~25%. Суммы совпали — данные дошли без искажений.
Важно: здесь нужна синхронизация (в коде — handshake через очередь ready),
иначе дочерний процесс мог прочитать данные до того, как родитель их запишет.

## Задание 4. Таблица

| Механизм | Нужна ли синхронизация программисту | Объём данных | Время (наш случай) |
|----------|--------------------------------------|--------------|---------------------|
| FIFO | нет (блокировки внутри ядра) | поток байт | для больших объёмов медленно: каждое чтение/запись — системный вызов |
| Pipe | нет | поток байт | самый медленный для больших данных: сериализация + 2 копирования через ядро (0.642s на 10^7 чисел) |
| Unix-сокет | нет | поток байт | быстрее FIFO (данные в памяти ядра, без inode-диска), тоже копирования |
| SharedMemory | **да** (семафоры/блокировки) | общий сегмент | самый быстрый (0.483s): нет системных вызовов в цикле передачи |

Разделяемая память — самый быстрый механизм, потому что после mmap данные
не ходят через ядро. Именно поэтому она и самый опасный: ядро не защищает
данные от одновременного доступа — всю синхронизацию пишет программист.

## Выводы
IPC через ядро (pipe, FIFO, сокеты) прост и безопасен, но каждое копирование
стоит переключения в режим ядра. Разделяемая память даёт максимальную
пропускную способность ценой ручной синхронизации.
