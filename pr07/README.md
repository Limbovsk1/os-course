
# ПР-7. Межпроцессное взаимодействие — IPC (вариант B)

## Цель
Сравнить механизмы IPC: именованный канал, Unix-сокет, разделяемая память.

## Задание 1. FIFO (именованный канал)
Терминал 1:
```
python3 fifo_server.py
```
Терминал 2:
```
python3 fifo_client.py 3 4
python3 fifo_client.py 10 20
```

Выводы:

```
<ВСТАВИТЬ ВЫВОД клиента>
```

Сервер последовательный: клиенты обслуживаются по очереди, пока один клиент
не получил ответ, другой ждёт в open()/read().

## Задание 2. Unix-сокеты, параллельные клиенты
Терминал 1:
```
python3 unix_server.py
```
Терминал 2 (несколько раз, в т.ч. одновременно из разных терминалов):
```
python3 unix_client.py 5 6
```

Вывод:

```
<ВСТАВИТЬ ВЫВОД>
```

Отличие: сервер форкает процесс на каждого клиента — клиенты обслуживаются
параллельно, не дожидаясь друг друга.

## Задание 4. Таблица

| Механизм | Нужна ли синхронизация программисту | Объём данных | Время (10^7 чисел / наше сообщение) |
|----------|--------------------------------------|--------------|-------------------------------------|
| FIFO     | нет (канал сам блокирует)          | поток байт   | FIFO медленный для больших объёмов, одно копирование |
| Pipe     | нет                                  | поток байт   | самый медленный: pickle + 2 копирования (parent->kernel->child) |
| Unix-сокет | нет                                | поток байт   | быстрее FIFO (нет дискового inode в пути), тоже копирования |
| SharedMemory | ДА (нужны семафоры/блокировки)   | общий сегмент| самый быстрый: 2 копирования без ядра в цикле |

Разделяемая память быстрая, потому что после mmap данные не ходят через ядро
(нет системных вызовов на каждую порцию), но именно поэтому опасна: никто
не защищает данные от одновременного доступа — синхронизацию пишем сами.

## Выводы
IPC через ядро (pipe, fifo, сокеты) прост и безопасен, но каждое копирование
стоит перехода в режим ядра. Разделяемая память даёт максимальную
пропускную способность ценой ручной синхронизации.
