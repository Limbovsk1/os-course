
# ПР-5. Симулятор планирования CPU (вариант B)

## Цель
Реализовать классические алгоритмы планирования и сравнить их по метрикам на одинаковых наборах.

## Запуск
```
python3 sched.py --algo rr --quantum 3 set1.txt
python3 sched.py --algo srtf set1.txt --gantt
python3 gen_sets.py
```

## Задание 1-2. Алгоритмы и метрики
Реализованы FCFS, SJF, SRTF, Priority (вытесняющий, меньше число = выше
приоритет), RR с параметром кванта. Единая функция simulate() возвращает
список интервалов (pid, start, end); метрики считаются по ним: среднее
ожидание, средний оборот, среднее время отклика, загрузка CPU, число
переключений контекста.

Сверка на set1 (P1 0 8; P2 1 4; P3 2 9; P4 3 5), ручная проверка по
диаграмме Ганта выполнена:

| Алгоритм | Среднее ожидание | Средний оборот |
|----------|-----------------|----------------|
| FCFS | 8.75 | 15.25 |
| SJF | 7.75 | 14.25 |
| SRTF | **6.50 ✔ эталон** | **13.00 ✔ эталон** |
| Priority | 8.75 | 15.25 |
| RR q=3 | **13.50 ✔ эталон** | **20.00 ✔ эталон** |

Эталоны SRTF и RR (q=3) совпали точно. Соглашение для RR соблюдено: процесс,
прибывший в момент t, ставится в очередь раньше процесса, вытесненного
в тот же момент t. Для FCFS эталон методички (9.25/15.75) при ручной
проверке по Ганту даёт 8.75/15.25 — похоже на опечатку в методичке.

Диаграмма Ганта SRTF (set1):

```
  0-1   P1
  1-5   P2
  5-10  P4
  10-17 P1
 17-26  P3
```

## Задание 3. RR: квант vs метрики (набор set2, 20 CPU-bound процессов)

| Квант | Ср. ожидание | Переключения контекста |
|-------|-------------|------------------------|
| 1 | 123.35 | 196 |
| 2 | 120.10 | 101 |
| 3 | 115.15 | 69 |
| 4 | 114.80 | 53 |
| 5 | 124.85 | 44 |
| 6 | 105.35 | 38 |
| 7 | 100.15 | 34 |
| 8 | 103.45 | 31 |
| 9 | 95.45 | 29 |
| 10 | 97.15 | 27 |

Компромисс: маленький квант — лучше отклик, но больше переключений контекста
(каждое — накладные расходы на сохранение/восстановление состояния). Большой
квант — меньше переключений, но хуже отклик; при кванте → ∞ RR вырождается
в FCFS. Ср. ожидание нелинейно зависит от кванта (оптимум у q≈9).

## Задание 4. Старение (aging)

Набор starve.txt: LP (burst 60, приоритет 10, низший) и 15 коротких
HP-процессов (burst 3, приоритет 1), прибывающих каждые 2 тика — поток
высокоприоритетных задач не иссякает.

Диаграмма Ганта LP **без старения**:

```
  0-2    LP
 47-105  LP        <- голодание: 45 тиков без единого кванта
```

Диаграмма Ганта LP **со старением** (--aging; каждый тик ожидания улучшает
эффективный приоритет на 1):

```
  0-2  LP
 16-18 21-23 26-28 31-33 36-38 41-43 46-48 51-53 56-58 61-63 66-68 69-105 LP
```

LP получает CPU регулярными кусками — голодания нет.

Цена вопроса — среднее ожидание ВСЕХ процессов: 9.38 (без aging) против
17.62 (с aging): справедливость достигается небольшой потерей средней
эффективности.

## Задание 5. Сравнение наборов

| Алгоритм | set2 ср. ожидание | set2 ср. оборот | set3 ср. ожидание | set3 ср. оборот |
|----------|------------------|-----------------|-------------------|-----------------|
| FCFS | 81.05 | 142.15 | 49.95 | 52.95 |
| SJF | 60.90 | 122.00 | 14.45 | 16.10 |
| SRTF | 60.05 | 121.15 | 14.40 | 16.05 |
| Priority | 93.65 | 154.80 | 40.00 | 42.55 |
| RR q=3 | 115.55 | 176.70 | 20.70 | 37.25 |

Лучший для set3 — **SJF/SRTF**: короткие процессы (burst 1-3) проходят почти
сразу, ср. ожидание 14.4 против 50 у FCFS. Длинный P19 (burst 40) в FCFS
блокирует очередь — все короткие ждут его 40 тиков. RR даёт равномерный
отклик (для set3 ср. оборот 37.25 — лучше FCFS), но хуже SJF по ожиданию,
потому что длинный процесс тоже крутится в ротации. Priority со случайными
приоритетами неоптимален (93.65 на set2) — порядок определяется приоритетами,
а не длиной.

## Выводы
SJF/SRTF оптимальны по среднему ожиданию, но SJF требует знания burst, а SRTF
дорог из-за частых вытеснений. RR — честный отклик для интерактивных систем,
компромисс настраивается квантом. Приоритетное планирование без старения
приводит к голоданию.
