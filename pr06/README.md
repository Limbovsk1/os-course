
# ПР-6. Синхронизация (вариант B)

## Цель
Устранить гонки, применить семафоры и условные переменные, решить
«производитель–потребитель».

## Задание 1-2. Кольцевой буфер без queue.Queue
```
python3 pc_bounded.py sem     # (а) два семафора + мьютекс
python3 pc_bounded.py cond    # (б) мьютекс + условная переменная
```

Ожидаемый вывод (оба варианта):

```
[<вариант>] OK: все 1000 элементов потреблены ровно один раз
```

Инвариты, проверенные в коде: каждый элемент потреблён ровно один раз
(массив-счётчик consumed), буфер не переполняется (семафор empty / условие
while count == BUF_SIZE). Нарушения логируются списком индексов.

Идея варианта (а): семафор empty стартует с BUF_SIZE и «выпускает» производителя
только при свободном слоте; full стартует с 0 и не даёт потребителю читать
пустоту; мьютекс защищает сам буфер.

## Задание 3. Барьер на условной переменной
```
python3 barrier_cond.py
```

Вывод:

```
<ВСТАВИТЬ ВЫВОД>
```

Барьер: последний пришедший обнуляет счётчик и делает notify_all,
остальные ждут в cond.wait().

## Задание 4. Потерянное пробуждение
```
python3 lost_wakeup.py
```

Вывод:

```
<ВСТАВИТЬ ВЫВОД>
```

Ломается при таком чередовании: два потребителя спят в wait(), производитель
кладёт два элемента, но уведомляет notify() только один раз — один wait
остаётся без сигнала навсегда, хотя элемент в буфере есть. Проверка через if
не защищает от повторной проверки: сигнал мог прийти ДО того, как поток встал
в очередь ожидания. Поэтому всегда while + notify_all().

## Выводы
Семафоры удобны для счётных ресурсов (слоты буфера), условные переменные —
для сложных условий. Классические ошибки: if вместо while (потерянное
пробуждение) и notify вместо notify_all.
