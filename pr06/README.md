
# ПР-6. Синхронизация (вариант B)

## Цель
Устранить гонки, применить семафоры и условные переменные, решить задачу
«производитель–потребитель» без queue.Queue.

## Задание 1-2. Кольцевой буфер на 5 элементов

```
python3 pc_bounded.py sem
python3 pc_bounded.py cond
```

Вывод:

```
[семафоры] OK: все 1000 элементов потреблены ровно один раз
[условная переменная] OK: все 1000 элементов потреблены ровно один раз
```

3 производителя, 2 потребителя, 1000 элементов, обе реализации проходят
проверку инвариантов (не «на глаз»): массив-счётчик consumed — каждый
элемент потреблён ровно один раз; буфер не переполнялся.

Вариант (а) — семафоры: empty стартует с 5 и «выпускает» производителя только
при свободном слоте; full стартует с 0 и не даёт потребителю читать пустоту;
мьютекс защищает критическую секцию (хвост/голова буфера).

Вариант (б) — условная переменная: производитель ждёт `while count == BUF_SIZE`,
потребитель — `while count == 0`, обе стороны делают notify() после изменения
состояния. Условие всегда проверяется while-ом внутри with cond.

## Задание 3. Барьер на условной переменной

```
python3 barrier_cond.py
```

Вывод:

```
OK: барьер работает, фазы не перемешиваются
```

4 потока, 3 фазы. Последний пришедший на барьер (arrived == N) обнуляет
счётчик и делает notify_all(), остальные ждут в cond.wait(). Проверка:
в журнале phase_log для каждой фазы присутствуют все 4 потока.

## Задание 4. Потерянное пробуждение

```
python3 lost_wakeup.py
```

Вывод:

```
producer: count=1, notify отправлен
ПОТЕРЯННОЕ ПРОБУЖДЕНИЕ: notify пришёл раньше wait — сигнал потерян, жду дальше
лечение: проверять условие while-ом внутри той же критической секции
```

Ломается при таком чередовании: потребитель проверил условие (count == 0)
и решает ждать, но между проверкой и cond.wait() вклинивается производитель:
делает count=1 и notify() — а ждущих ещё нет, сигнал уходит в никуда.
Потребитель затем всё равно входит в wait() и спит вечно, хотя данные есть.

Лечение: проверка условия и wait должны быть атомарны — while (не if!)
внутри одного `with cond`. Тогда даже если сигнал пришёл «мимо»,
while перепроверит условие и не войдёт в ожидание зря.

## Выводы
Семафоры удобны для счётных ресурсов (слоты буфера), условные переменные —
для сложных условий. Два классических правила: всегда while вокруг wait
(иначе потерянное пробуждение) и notify_all, когда будим несколько
потребителей с одинаковым условием.
