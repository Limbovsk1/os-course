
# ПР-2. Bash и системные вызовы (вариант B)

## Цель
Освоить bash-скрипты и увидеть, как программа обращается к ядру через системные вызовы.

## Подготовка данных
```
python3 gen_logs.py
```

## Задание 1. report.sh
```
chmod +x report.sh
./report.sh data ERROR
./report.sh data ERROR --top 3
./report.sh data WARN
./report.sh                      # справка, код возврата 1
echo $?
./report.sh /nonexistent ERROR   # проверка ошибки
```

Вывод таблицы ERROR:

```
<ВСТАВИТЬ ВЫВОД>
```

## Задание 2. Режим --top N и проверка каталога
Реализовано: при отсутствии аргументов — справка и `exit 1`; при несуществующем
каталоге — сообщение об ошибке и ненулевой код возврата. См. выводы выше.

## Задание 3. strace hello.py
```
strace -f -o trace.txt python3 hello.py data/01.log
wc -l trace.txt
grep -c "read" trace.txt
grep "read(" trace.txt | head -5
```

Сколько всего системных вызовов и сколько из них — чтение файла:

```
<ВСТАВИТЬ: wc -l trace.txt и число read к данному файлу>
```

Почему остальные вызовы — накладные расходы интерпретатора: python3 стартует,
читает конфиги/локали (openat на /usr/lib/python3.10/..., fstat, mmap библиотек),
выделяет память (brk/mmap), и только небольшая часть вызовов относится
к нашему файлу.

## Задание 4. cat vs python3

```
strace -c -o /tmp/cat.trace cat data/01.log
strace -c -o /tmp/py.trace python3 hello.py data/01.log
tail -3 /tmp/cat.trace
tail -3 /tmp/py.trace
```

Число вызовов (строка total из каждого файла):

```
cat:      <ВСТАВИТЬ>
python3:  <ВСТАВИТЬ>
```

Вывод: cat на порядки экономнее — это компилированная программа, которая
сразу читает файл; python3 тащит интерпретатор, импорты и рантайм,
поэтому системных вызовов в десятки-сотни раз больше.

## Выводы
Написан отчётный скрипт на bash (grep/awk/sort), освоен strace.
Видно, что каждая программа работает с ядром только через системные вызовы,
а интерпретируемые языки имеют большие накладные расходы на старте.
