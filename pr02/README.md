
# ПР-2. Bash и системные вызовы (вариант B)

## Цель
Освоить bash-скрипты и увидеть, как программа обращается к ядру через системные вызовы.

## Подготовка данных
```
python3 gen_logs.py        # -> 50 файлов создано в data/
```

## Задание 1. report.sh — таблица «модуль → число сообщений»

```
chmod +x report.sh
./report.sh data ERROR
```

Вывод:

```
disk       191
db         177
net        174
auth       169
fs         158
```

```
./report.sh data ERROR --top 3
```

Вывод:

```
disk       191
db         177
net        174
```

```
./report.sh data WARN
```

Вывод:

```
net        298
fs         289
disk       275
auth       259
db         252
```

## Задание 2. Режим --top N и проверка каталога
Реализовано: при отсутствии аргументов — справка `Usage: report.sh <dir> <ERROR|WARN> [--top N]`
и `exit 1`; при несуществующем каталоге — `Error: directory '/nonexistent' not found`
и ненулевой код возврата.

Скрипт: grep выбирает строки с уровнем, awk извлекает module=..., sort|uniq -c
считает, sort -rn сортирует по убыванию, awk с top обрезает таблицу.

## Задание 3. strace hello.py

```
strace -f -o trace.txt python3 hello.py data/01.log
wc -l trace.txt
grep -c "read" trace.txt
```

- Всего системных вызовов: **667**
- Из них относятся к чтению нашего файла (read): **81** (чтение идёт кусками
  по 65536 байт, пока файл не кончится)

Почему остальные ~586 вызовов — накладные расходы интерпретатора: python3 при
старте открывает и читает кучу служебных файлов (openat/read на
/usr/lib/python3.10/..., локали, encodings), делает mmap библиотек,
brk/mmap для кучи, fstat, ioctl терминала и т.д. Лишь малая часть вызовов
относится к нашему файлу.

## Задание 4. cat vs python3

```
strace -c -o /tmp/cat.trace cat data/01.log
strace -c -o /tmp/py.trace python3 hello.py data/01.log
```

Итоговые строки (total из каждого файла):

```
cat:      122 системных вызова
python3:  665 системных вызовов
```

Вывод: на одном и том же файле cat делает в ~5 раз меньше системных вызовов —
это компилированная программа, которая сразу читает файл. python3 тащит
интерпретатор, импорты и рантайм: сотни вызовов до и после полезной работы.
Поэтому для коротких задач «текстовая утилита» почти всегда быстрее скрипта.

## Выводы
Написан отчётный скрипт на bash (grep/awk/sort), освоен strace (-f следить за
дочерними процессами, -c статистика по вызовам). Видно, что каждая программа
работает с ядром только через системные вызовы, а интерпретируемые языки
имеют большие накладные расходы на старте.
